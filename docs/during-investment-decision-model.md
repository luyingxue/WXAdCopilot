# 挂车短视频投中决策模型设计

**文档状态：** 建设输入稿  
**适用产品：** WXAdCopilot  
**适用范围：** 视频号挂车短视频加热  
**不包含：** 无组件内容、直播、小游戏、短剧、APP、投前筛选模型

---

## 1. 核心结论

WXAdCopilot 的核心价值不是预测一条视频最终是否会爆，也不是破解微信内部竞价
算法，而是：

> 在挂车视频以最小额度开始投放后，持续采集真实订单状态，判断继续观察、停止
> 跟投、同策略跟投或调整策略跟投。

系统采用量化投资的基本结构：

```text
投前统计信号
→ 最小额度试仓
→ 投中持续跟踪
→ 判断持有、止损、同策略加仓或调整策略加仓
→ 投后退款回补与最终复盘
```

投前筛选已有第一版实现，本设计不重新定义投前模型。当前约定为：符合投前统计
条件的挂车视频，一律以最小金额开始投放。

---

## 2. 模型定位

### 2.1 模型要解决的问题

模型持续回答以下问题：

1. 当前订单能否正常消耗？
2. 付费流量是否撬动了额外自然流量？
3. 当前资金使用效率是否超过经营保本线？
4. 最近新增资金的流量杠杆和经营效率是在改善、稳定还是衰减？
5. 是否应该停止新增投入？
6. 如果继续投入，应沿用当前投法还是调整投法？

模型最重要的判断不是“累计结果是否还不错”，而是：

> 如果现在再投入下一单位资金，其边际回报是否仍然值得。

### 2.2 模型不解决的问题

- 不还原微信逐次流量竞价和结算公式；
- 不预测单个用户是否会购买；
- 不承诺精确预测下一笔订单的最终 ROI；
- 不让大语言模型直接决定资金操作；
- 不在当前阶段自动创建、修改、追加或停止官方订单。

首期只提供辅助决策和告警，所有官方资金操作均由用户确认执行。

## 3. 为什么核心采用计算模型

投中决策依赖真实消耗、点击、成交、退款和 GMV，这些指标均可通过确定公式计算。
资金决策必须具备：

- 可解释；
- 可复现；
- 可审计；
- 相同输入产生相同输出；
- 明确处理零值、缺失值、样本不足和数据延迟。

因此核心技术形态为：

```text
指标计算引擎
+ 统计判断
+ 订单状态机
+ 风险规则
```

AI 只作为辅助层：

- 将计算结果翻译为易懂说明；
- 总结可能的异常原因；
- 生成下一轮测试方案候选；
- 帮助用户理解风险和不确定性。

AI 不得绕过预算、止损、样本量和数据成熟度等硬规则。

未来订单样本充分后，可以增加概率模型、贝叶斯更新或上下文多臂老虎机，但仍须
受确定性风险规则约束。

## 4. 黑盒竞价系统认知

视频号加热平台对外部使用者而言是一个规则不完全透明、持续变化且带随机性的
黑盒系统。

可简化理解为：

```text
平台不断产生用户展示机会
→ 广告主的自动投标系统结合预算、目标和用户转化概率动态参与竞价
→ 平台综合出价、预测转化率、内容质量等因素进行排序
→ 获胜内容取得展示机会
→ 多次竞价形成总消耗和总转化
```

报表中的平均点击成本是：

```text
平均商品点击成本 = 总实际消耗 / 商品点击数
```

它是订单累计结果，不应解释为每一次点击都按照该固定价格成交。

系统不尝试推断黑盒内部精确规则，而是记录：

> 在特定账号、视频、商品和投放配置下，平台实际返回了什么结果。

## 5. 挂车视频可用加热目标

当前实际界面确认有五个目标：

1. 商品点击数；
2. 商品成交数；
3. 商品净成交数；
4. 商品 ROI；
5. 商品净成交 ROI。

它们可分为三层：

| 层级 | 加热目标 | 优化方向 |
|---|---|---|
| 浅层 | 商品点击数 | 商品组件点击人数 |
| 成交层 | 商品成交数、商品净成交数 | 成交次数或剔除快速退款后的净成交次数 |
| 收益层 | 商品 ROI、商品净成交 ROI | GMV 或净 GMV 与订单消耗之比 |

“净”口径按当前官方规则剔除 1 小时内退款：

```text
商品净成交 ROI
=（成交 GMV - 1 小时内退款 GMV）/ 订单消耗金额
```

平台净成交口径不等于最终结算口径。1 小时后发生的退款仍需在投后回补。

## 6. 首笔订单：最小试仓规则

新账号进入投中系统后的首笔挂车视频订单，当前共识配置为：

```text
加热目标：商品点击数
出价方式：放量加热
投放金额：平台允许的最小金额
定时加热：不定时
加热时长：24 小时
人群定向：默认加热方案
```

### 6.1 选择商品点击数

商品点击是最浅层转化目标，从零开始更容易形成转化样本。首笔订单不是假定商品
点击永远最优，而是用最低风险取得该账号的第一份真实投放基线。

### 6.2 选择放量加热

控成本加热需要预先填写目标转化成本。账号没有历史付费数据时，该价格缺少真实
依据，出价过低会导致订单无法消耗，出价过高则失去控成本意义。

首笔放量订单用于发现：

- 能否正常消耗；
- 实际商品点击成本；
- 付费点击成交率；
- 实际成交与净成交成本；
- 实际商品 ROI 与商品净成交 ROI。

### 6.3 选择 24 小时

24 小时给平台更充分的探索和消耗时间，减少短时间强制消耗对首笔基线的干扰。
计划时长不等于实际运行时长，系统必须另外记录首次曝光、首次消耗、预算耗尽和
订单结束时间。

### 6.4 选择默认人群

首笔订单优先减少人工变量，由平台依据视频、商品、账号和用户行为寻找点击人群。
若商品存在无法配送、法定限制或绝对不适用人群，只保留必要的硬性经营限制。

首笔订单结束后，再依据实际人群画像、点击、成交和 ROI 判断是否需要自定义定向。

## 7. 放量加热与控成本加热

### 7.1 放量加热

用户提供预算和加热目标，由平台动态竞价并尽量取得目标转化。首笔订单采用放量
加热，以发现真实市场成本。

### 7.2 控成本加热

用户额外提供目标转化成本。该价格约束订单整体平均成本，不代表每个转化均以固定
价格获得。

控成本加热适合在已有放量基线后测试：

```text
历史实际点击成本
→ 设定下一笔目标点击成本
→ 检查能否消耗及实际成本是否下降
```

### 7.3 成本保障边界

商品点击目标适用成本保障时，至少需要：

- 选择控成本加热；
- 未采用加速起量；
- 点击数不少于 2；
- 消耗不少于 500 微信豆；
- 实际消耗与预期消耗之比超过 120%；
- 订单、视频和作者满足其他官方条件。

成本保障发放的是有有效期和使用限制的成本保障券，不是现金或微信豆退款。模型
不得将保障券按现金收入直接计入真实 ROI。

## 8. 数据模型与归因优先级

### 8.1 跨端关联

当前已确认 Promote 返回 `feedExportId`、`globalExportId` 等视频标识，Commerce
使用 `export_id`。系统不得在未经过真实订单验证前假设这些标识始终相同。

```text
Promote promotionId
→ Promote feedExportId / globalExportId
→ 经验证的视频标识映射
→ Commerce export_id
```

订单以 Promote 返回的 `promotionId` 作为投放侧唯一键。视频映射需保存标识类型、
标识值、来源和验证状态；不得仅凭发布时间或标题长期关联。

### 8.2 数据来源

加热平台提供或待真实订单验证：

- 订单目标与配置；
- 总预算和实际消耗；
- 加热播放与商品点击；
- 商品成交和净成交；
- 成交 GMV、净成交 GMV、ROI；
- 10 分钟、1 小时和 1 天粒度的订单时序指标；
- 观众画像和互动深度指标；
- 自投视频在加热开始后 72 小时内的自然流量溢出。

当前前端接口契约已确认自然流量溢出字段包括：

```text
feedOverflowExposureCount   溢出播放
feedOverflowLikeCount       溢出点赞
feedOverflowFavCount        溢出收藏
feedOverflowCommentCount    溢出评论
feedOverflowFollowCount     溢出视频号关注
feedOverflowBizFollowCount  溢出公众号/服务号关注
feedOverflowForwardCount    溢出分享
```

必须严格区分：

- `exposureCount`：加热带来的播放；
- `feedOverflowExposureCount`：加热撬动的自然溢出播放；
- “超额效果”：实际目标效果超过预计效果的部分，不等于自然流量溢出。

自然流量溢出目前仅确认对自投视频展示；不同加热目标下是否返回完整字段，仍须使用
真实订单验证。

电商罗盘提供：

- 视频累计商品曝光和点击；
- 视频累计成交订单、GMV；
- 视频累计退款订单、退款 GMV。

商品数据提供：

- 商品身份；
- 当前佣金率及佣金率快照。

### 8.3 归因优先级

1. 若加热平台直接返回订单级 GMV、净 GMV 和 ROI，优先使用官方订单级数据；
2. 若只能取得视频累计成交数据，则用相邻快照差分观察视频增量；
3. 视频级增量不得直接等同为订单级贡献；
4. 同一视频同时存在多笔订单时，未验证重叠归因规则前，不拆分订单级 GMV；
5. 需要订单级准确决策时，应避免同一视频多笔订单时间重叠；
6. 投后使用后续退款和官方结算佣金校正最终收益。

## 9. 核心计算指标

投中决策同时采用两条主线：

```text
流量杠杆线：付费流量是否撬动了额外自然流量
经营收益线：点击、成交和佣金收益是否覆盖投放成本
```

流量杠杆高不代表经营收益一定合格；经营收益合格也不要求自然流量杠杆一定大于
1。模型必须分别计算，再形成综合建议。

### 9.1 累计流量杠杆

```text
累计自然流量杠杆
= 累计自然溢出播放 / 累计加热播放
= feedOverflowExposureCount / exposureCount
```

课程中的初始经验规则为：

```text
自然流量杠杆 > 1：具备继续观察或跟投价值
自然流量杠杆 ≤ 1：不应仅凭撬动自然流的目标继续加仓
```

该阈值是策略初始值，不是平台规则。实际使用时还必须结合样本量、运行时间、经营
收益和边际趋势。

### 9.2 累计经营指标

```text
平均点击成本
= 累计消耗 / 累计商品点击数

累计成交成本
= 累计消耗 / 累计商品成交数

累计净成交成本
= 累计消耗 / 累计商品净成交数

累计商品 ROI
= 累计成交 GMV / 累计消耗

累计商品净成交 ROI
= 累计净成交 GMV / 累计消耗
```

### 9.3 边际指标

相邻有效快照之间计算：

```text
边际自然流量杠杆
= 新增自然溢出播放 / 新增加热播放

边际点击成本
= 新增消耗 / 新增商品点击数

边际净成交成本
= 新增消耗 / 新增商品净成交数

边际商品净成交 ROI
= 新增净成交 GMV / 新增消耗
```

边际指标用于判断新增资金效率，累计指标用于观察总体结果。累计自然流量杠杆或
累计 ROI 合格，但对应边际指标持续下降时，不应仅凭累计结果继续加仓。

### 9.4 佣金与经营保本线

平台 ROI 是 GMV 口径，不等于利润 ROI。对达人佣金场景，可先估算：

```text
估算净佣金
= 净成交 GMV × 当时佣金率

估算佣金 ROI
= 估算净佣金 / 实际消耗
```

最终收益需在投后使用官方结算佣金、全部退款和其他可用成本校正。

所有除法必须显式处理分母为零：

- 分母为零时结果为 `null`；
- 不得记为 0 或无穷大；
- `null` 表示当前不可判断。

## 10. 投中订单状态机

建议第一版状态：

| 状态 | 含义 |
|---|---|
| `WAITING_DATA` | 消耗、点击或成交样本不足 |
| `NOT_SPENDING` | 订单未正常产生消耗 |
| `HEALTHY` | 当前成本与边际收益正常 |
| `IMPROVING` | 边际效率持续改善 |
| `DECAYING` | 边际效率持续下降 |
| `BELOW_BREAK_EVEN` | 有效样本下持续低于经营保本线 |
| `READY_TO_ADD` | 满足跟投条件 |
| `NO_MORE_ADD` | 当前订单可继续结算，但不建议新增投入 |
| `ENDED_PENDING_ATTRIBUTION` | 订单结束，等待成交或退款回传 |
| `SETTLED` | 归因与退款观察窗口结束 |

状态判断必须同时考虑：

- 样本量；
- 数据回传延迟；
- 实际消耗比例；
- 累计与边际自然流量杠杆；
- 累计收益；
- 边际收益；
- 趋势持续窗口；
- 订单目标及其归因周期。

不得因短期零成交或单笔偶然成交直接触发强结论。

## 11. 决策动作

第一版模型输出以下辅助动作：

| 动作 | 含义 |
|---|---|
| `HOLD` | 继续观察，不新增操作 |
| `STOP_LOSS` | 建议停止当前订单或不再投入 |
| `ADD_SAME` | 建议沿用当前策略追加最小单位资金 |
| `ADD_CHANGED` | 建议调整目标、出价方式或定向后跟投 |
| `NO_ADD` | 当前订单可继续，但停止新增投入 |
| `WAIT_ATTRIBUTION` | 等待成交、净成交或退款数据回传 |

动作输出必须附带证据：

```text
当前状态
触发规则
样本量
累计指标
边际指标
保本线
数据成熟度
主要风险
```

## 12. PDCA 运行方式

### Plan

依据投前统计信号和上一笔真实订单，确定本轮最小仓位及唯一主要测试变量。

### Do

由用户创建订单；系统按允许频率抓取订单、视频成交及退款快照。

### Check

检查：

1. 可投性：是否正常消耗；
2. 经济性：累计与边际成本、ROI 是否合格；
3. 杠杆性：付费播放是否持续带来自然流量溢出；
4. 稳定性：结果是否持续，还是由偶然成交或短时流量波动造成；
5. 成熟度：自然溢出、成交和退款数据是否已充分回传。

### Act

输出继续观察、止损、同策略跟投、调整策略跟投或停止新增投入建议，并将最终结果
写入账号、商品、视频和策略历史。

系统不是一次性寻找“永久最优策略”，而是在平台、市场和内容持续变化的条件下，
不断更新当前有效策略。

## 13. 第一阶段建设优先级

### P0：真实订单数据验证

使用真实挂车订单验证以下 RPC 的请求和响应：

- `searchFeedPromotionOrderList`
- `getFeedPromotionOrderOverview`
- `getFeedPromotionOrdersTsIndicator`
- `getFeedPromotionOrderDetail`
- `getFeedPromotionOrderIndicatorDetail`

重点确认：

- 订单目标和完整配置；
- 实际消耗单位；
- 点击、成交、净成交字段；
- GMV、净 GMV 和 ROI 是否为订单级；
- `exposureCount` 和各项 `feedOverflow*` 字段的单位、更新频率及适用目标；
- 自然流量溢出的 72 小时统计起止边界；
- 10 分钟、1 小时、1 天时序是累计值还是区间增量；
- 数据回传延迟；
- 订单结束后的继续归因周期；
- 不同目标下字段是否缺失；
- 同视频多订单的归因边界。

### P1：订单快照与指标引擎

- 建立 `campaign_orders` 和 `order_snapshots`；
- 保存原始响应及规范字段；
- 计算累计与边际自然流量杠杆、经营成本和收益指标；
- 建立数据成熟度和空值规则；
- 关联商品佣金快照与视频成交快照。

### P2：状态机与建议

- 实现可投性判断；
- 实现累计/边际收益状态；
- 实现保本线；
- 输出六类辅助动作；
- 提供完整证据和审计记录；
- 暂不自动操作官方订单。

### P3：投后校正与策略学习

- 回补后续退款；
- 接入最终结算佣金；
- 生成订单、视频、商品和账号级复盘；
- 比较不同目标、出价和人群的真实结果；
- 在样本充分后研究概率模型。

## 14. 验收标准

第一版模型有效不以“准确预测最终 ROI”为标准，而以以下结果衡量：

1. 能稳定、准确地还原每笔订单的实际状态；
2. 能区分无法消耗与能消耗但不赚钱；
3. 能区分付费播放与由其撬动的自然流量溢出；
4. 能区分累计杠杆、累计收益与新增资金的边际效率；
5. 能避免在样本不足和数据延迟时过早止损；
6. 每条建议均可追溯到明确数据和规则；
7. 同类订单中，接受模型建议后的亏损率、自然流量杠杆、净 ROI 或资金利用效率
   优于固定投法；
8. 投后退款回补后，可以评估投中建议是否正确并修正规则。

---

## 15. 一句话产品定义

> 投前用统计规则决定是否以最小金额试仓；投中用真实订单时序数据决定观察、
> 止损或动态跟投；投后用最终退款和收益校正策略。
