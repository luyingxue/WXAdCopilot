# 微信视频号量化投流助手

## 第一阶段：三平台 Playwright 数据探索任务说明书

**版本：** v0.1  
**日期：** 2026-07-23  
**适用对象：** 可运行本地 Playwright 的开发 Agent、自动化程序或工程师  
**任务性质：** 有头浏览器、人工扫码、只读探索、接口普查、数据建模前置研究

---

## 1. 任务目标

本阶段不按照预设的数据需求清单逐项寻找字段，而是对三个运营后台进行开放式探索：

1. 打开每个平台的关键业务页面。
2. 记录页面能够展示和操作的全部数据能力。
3. 监听页面产生的 XHR/Fetch 请求。
4. 分析接口用途、请求参数、响应结构、分页方式和更新机制。
5. 建立完整的接口目录、字段字典和实体关系。
6. 识别三个平台之间可用于关联视频、商品、订单和投放计划的键。
7. 所有平台探索完成后，再与业务目标进行差距分析。

最终需要回答的不是“理想字段是否存在”，而是：

> 三个平台实际上能够稳定提供什么数据，这些数据之间能否关联，以及能够支撑哪些自动分析能力。

## 3. 强制执行边界

### 3.1 允许的操作

- 打开和刷新页面。
- 切换只读标签页。
- 查看列表和详情。
- 调整日期、分页、排序和筛选条件。
- 展开只读信息。
- 监听、保存和分析网络响应。
- 截取用于核对字段的页面截图。
- 下载官方数据报表，但不得覆盖原始文件。

### 3.2 禁止的操作

- 创建或追加投放订单。
- 暂停、终止、修改或删除订单。
- 修改视频、商品、账号或店铺信息。
- 发布内容、发送消息或提交表单。
- 发起充值、支付、退款或提现。
- 绕过验证码、安全验证、限频或其他平台保护。
- 在日志和项目文件中保存账号密码、Cookie、Token、签名或完整认证请求头。

### 3.3 遇到以下情况必须暂停并等待人工处理

- 扫码登录。
- 验证码。
- 短信验证。
- 登录确认。
- 权限申请。
- 页面出现可能改变业务状态的确认按钮。
- 账号、店铺或视频号主体不明确。

## 4. 浏览器与登录态要求

### 4.1 浏览器模式

- 使用 Playwright 有头模式：`headless: false`。
- 优先使用本机 Chrome 通道。
- 首次登录由用户人工扫码。
- 浏览器窗口必须保持可见，便于用户接管。

### 4.2 持久化 Profile

使用 `launchPersistentContext` 保存本地登录态，但 Profile 不得放入 Git 仓库。

推荐位置：

```text
~/.wxadcopilot/browser-profiles/operator-01/
```

项目配置只允许记录 Profile 路径：

```env
WXAD_BROWSER_PROFILE=/absolute/path/to/private/profile
```

不得记录：

- 微信账号和密码
- Cookie 内容
- LocalStorage 内容
- Access Token
- Refresh Token
- 请求签名
- 完整请求头

项目的 `.gitignore` 至少应包含：

```gitignore
.env
.browser-profile/
playwright/.auth/
*.har
data/raw-private/
```

## 5. 总体探索方法

每个平台按照以下顺序执行。

### 步骤一：页面地图

记录：

- 页面名称。
- 页面 URL。
- 入口路径。
- 页面用途。
- 可见数据模块。
- 日期范围。
- 筛选项。
- 排序项。
- 分页方式。
- 是否有详情页。
- 是否提供导出。

### 步骤二：接口普查

清空本轮网络记录，然后：

1. 刷新目标页面。
2. 等待首屏数据加载完成。
3. 记录首屏产生的 XHR/Fetch。
4. 切换日期范围。
5. 执行一次分页。
6. 执行一次排序。
7. 执行一次筛选。
8. 打开一条记录的详情。
9. 如果安全，打开第二条记录验证结构是否一致。

不要只分析 URL 中带 `api` 的请求。所有返回 JSON、protobuf 包装数据或业务结构的请求都应纳入候选。

### 步骤三：接口分类

为每个接口判断用途：

- 列表接口
- 详情接口
- 汇总指标接口
- 趋势接口
- 配置/枚举接口
- 导出任务接口
- 导出文件接口
- 账号/权限接口
- 无关的日志、埋点或监控接口

### 步骤四：字段探索

完整遍历业务响应结构，记录：

- 字段路径。
- 原始字段名。
- 数据类型。
- 样例值，必须脱敏。
- 是否可能是 ID。
- 是否可能是时间。
- 是否可能是金额、计数、比例或状态枚举。
- 字段是否总是出现。
- 字段为空时的页面含义。
- 页面上的对应中文标签。
- 是否与其他接口重复。

不得只提取当前认为有用的字段。第一轮应保留完整字段目录，避免遗漏未来有价值的数据。

### 步骤五：实体与关系推断

识别响应中可能存在的实体：

- 账号
- 视频
- 作者/达人
- 店铺
- 商品
- SKU
- 交易订单
- 退款
- 投放订单/计划
- 投放目标
- 定向配置
- 数据快照

识别所有疑似关联键，包括但不限于：

```text
video_id
feed_id
object_id
export_id
uniq_id
finder_username
account_id
shop_id
product_id
spu_id
sku_id
order_id
campaign_id
promote_id
```

不要因为字段名称不同就认为不是同一个 ID。应通过样例值、长度、格式、页面内容和跨接口重复情况验证。

### 步骤六：重复读取与时效测试

对关键列表和详情接口至少重复读取两次，记录：

- 两次采集时间。
- 指标是否变化。
- 页面与接口是否同时更新。
- 接口是否返回服务端统计时间。
- 是否存在缓存。
- 请求是否需要时间范围。
- 能否查询历史数据。
- 历史范围上限。

### 步骤七：页面数值核对

对每类关键接口至少选择一条记录：

- 保存页面截图。
- 保存脱敏响应样例。
- 核对页面显示值与接口值。
- 记录单位换算。
- 记录比例是否使用小数或百分数。
- 记录金额单位是元、分、微信豆还是其他单位。

## 6. 网络响应采集要求

### 6.1 需要记录的元数据

```json
{
  "platform": "creator|commerce|promote",
  "page_name": "页面名称",
  "page_url": "脱敏后的页面地址",
  "captured_at": "ISO-8601",
  "request": {
    "method": "GET|POST",
    "url": "去除敏感查询参数后的接口地址",
    "resource_type": "xhr|fetch|document|other",
    "query_keys": ["只记录参数名"],
    "body_keys": ["只记录请求体字段名"]
  },
  "response": {
    "status": 200,
    "content_type": "application/json",
    "schema_hash": "响应结构哈希",
    "sample_file": "脱敏样例文件路径"
  }
}
```

### 6.2 原始响应处理

- 原始响应优先保存在本机私有目录。
- 写入项目的样例必须先脱敏。
- 对相同接口的多个响应保留不同场景样例，例如首页、分页、筛选和详情。
- 响应较大时可以只保留业务数据节点，但必须记录被裁剪的路径。
- 二进制或 protobuf 响应需记录 Content-Type、响应大小和可否解码。

### 6.3 必须脱敏的内容

- Cookie
- Authorization
- Token
- Ticket
- Signature
- Session ID
- CSRF Token
- 手机号
- 收货地址
- 买家昵称和头像
- 订单号，如可识别个人交易
- 其他个人信息和认证信息

ID 若需要用于跨接口映射，可在本地使用一致性哈希：

```text
raw_id → sha256(project_salt + raw_id)
```

同一个原始 ID 必须得到相同的脱敏 ID，以便验证跨接口关联。

## 8. 标准记录格式

### 8.1 页面地图

```markdown
## 页面名称

- 平台：
- URL：
- 入口路径：
- 页面用途：
- 可见数据：
- 日期范围：
- 筛选/排序：
- 分页：
- 详情入口：
- 导出能力：
- 触发的主要接口：
- 备注：
```

### 8.2 接口目录

```markdown
## 接口名称

- 平台：
- 触发页面：
- 触发动作：
- 方法：
- URL 模式：
- 用途：
- 请求参数：
- 分页方式：
- 返回实体：
- 顶层响应结构：
- 服务端时间字段：
- 历史范围：
- 更新延迟：
- 脱敏样例：
- 稳定性判断：
- 备注：
```

### 8.3 字段字典

| 字段路径 | 类型 | 页面标签 | 语义推断 | 单位 | 示例 | 出现条件 | 可信度 |
|---|---|---|---|---|---|---|---|

可信度：

- 高：页面标签、接口命名和数值核对均一致。
- 中：根据多个样例和上下文推断。
- 低：只有字段名称或单一样例支持。

### 8.4 ID 映射记录

| 来源平台 | 来源字段 | 目标平台 | 目标字段 | 样例是否相同 | 映射方式 | 可信度 |
|---|---|---|---|---|---|---|

映射方式：

- 直接相等
- 格式转换
- 映射接口
- 标题+发布时间
- 人工复核

## 9. 三平台探索顺序

### 第一轮：视频基础实体

从视频号助手的视频列表和视频详情开始，建立视频实体基准：

- 视频 ID 候选。
- 标题。
- 发布时间。
- 视频状态。
- 页面可见累计指标。
- 列表和详情之间的关系。

### 第二轮：单视频带货归因

进入电商罗盘或带货助手：

- 短视频列表。
- 单视频带货详情。
- 商品信息。
- 点击、下单、成交和退款数据。
- 视频 ID 是否与第一轮一致。

进入加热平台：

- 投放订单列表。
- 单笔订单详情。

- 预算与消耗。
- 订单状态。
- 投放结果。
- 目标和定向配置。
- 视频 ID 是否与前两轮一致。

### 第四轮：补充页面

完成三个核心链路后，再探索：

- 账号整体趋势。
- 关注者增长。
- 商品分析。
- 成交趋势。
- 导出能力。
- 配置与枚举接口。

## 10. 探索过程中的判断原则

### 10.1 不提前限定数据模型

第一轮只建立原始实体和字段目录，不强行套入预设数据库结构。

### 10.2 不把接口字段名直接当成业务定义

例如：

- `gmv` 可能表示下单、支付或结算金额。
- `view_count` 可能是累计播放、有效播放或某时间段播放。
- `follow_count` 可能是累计关注或新增关注。

必须通过页面标签、数值核对和多次采样确认。

### 10.3 不忽略配置和枚举接口

配置接口可能揭示：

- 投放目标类型。
- 订单状态。
- 人群类型。
- 地域层级。
- 统计口径。
- 数据刷新说明。

### 10.4 区分“平台提供”和“本地可推导”

每个指标标记为：

- 原始字段
- 多字段计算
- 跨平台关联计算
- 模型估算
- 当前无法得到

## 11. 最终差距分析

只有三个平台全部完成接口和字段普查后，才生成差距分析。

差距分析需要输出：

1. 平台直接提供的数据。
2. 可通过已有字段计算的数据。
3. 可通过周期快照得到的数据。
4. 可通过跨平台映射得到的数据。
5. 只能估算的数据。
6. 完全不可获得的数据。
7. 每类数据的稳定性、延迟和历史范围。
8. 对自动分析、自动告警和未来自动投放的支持程度。

最终结论按以下等级标记：

| 等级 | 定义 |
|---|---|
| 可生产使用 | 字段稳定、关联可靠、口径清楚、可持续读取 |
| 受限可用 | 可以读取，但延迟、口径或关联存在限制 |
| 仅供研究 | 依赖 DOM、估算或人工复核 |
| 不可用 | 无法稳定获得或无法解释 |

## 12. 完成标准

本任务完成需要同时满足：

- 三个平台的核心页面均已探索。
- 页面地图完整。
- 主要业务接口均有目录记录。
- 主要响应结构均有脱敏样例。
- 字段字典覆盖全部业务字段，而非只覆盖预设需求。
- 已识别视频、商品、订单和投放计划的 ID 候选。
- 已进行至少一次跨平台视频映射验证。
- 已对关键累计指标进行重复读取。
- 已记录数据刷新、缓存、历史范围和分页机制。
- 未在项目中保存登录凭证或个人信息。
- 已完成最终数据覆盖与差距分析。
